# 已确认需求

确认日期：2026-11-07（Asia/Shanghai）。本文记录产品目标与验收要求，不代表以下能力均已实现；实际进度见 [status.md](status.md)，技术决策见 [architecture.md](architecture.md)。

## 产品范围

- 名称「声笺 · Sonafolio」；工作区为当前目录下的 `sonafolio/`，Python 包与命令均为 `sonafolio`。
- 面向开源，支持 macOS 和 Windows。
- 优先实现可直接调用的处理核心和 CLI，后续封装桌面界面；HTTP API 按需提供，不作为桌面的前置条件。
- 输入以 M4A 为主，主要为中文；典型单条约 60 分钟，每天约 1 条。
- ASR、说话人区分和 LLM 分别提供适配器；支持本地、云端及混合组合。
- 已选定当前 LLM 接入服务为 DeepSeek API；密钥保存在本地工作区。
- 从用户配置的类目中分类，至少包括面试、问诊、快递；允许子类目，例如面试类型。
- 类目通过 Skill 扩展，支持独立配置 Prompt，持续迭代总结模板。
- 面试总结采用候选人视角，必须区分不同说话人。
- 补充确认：底层自动估计任意数量的说话人并输出稳定 ID；用户无需预先指定谁是候选人。LLM 根据各人内容推断角色并总结，无法确定时保留未知，角色修正属于可选能力。
- 工作区内管理环境、模型、缓存、临时文件和业务数据，不修改原有本机环境。
- 桌面端需要模型服务商、模型名与 API Key 设置，以及模型文件／缓存目录设置。
- 支持行业分类和 Prompt 的管理；具体信息层级由桌面设计稿评审确认。
- 录音文件管理至少支持重命名；标题与实际文件名的修改关系、冲突处理需在界面中明确。

## 目标行为

- 单文件与目录批处理；无需实时识别、常驻服务或分布式队列。
- 原始音频只读；转码产生派生文件，不覆盖原文件。
- ASR 文本、说话人区间、对齐结果分别保留，便于单独重跑与追溯。
- 说话人 ID 在同一录音内稳定，允许两人以上；默认不做跨录音声纹身份识别。
- 分清说话人 ID 与业务角色；LLM 根据对话内容推断角色，候选人角色允许手动覆盖，但不要求用户预先确认。
- 无法确认的归属、重叠说话和未识别片段应保留状态，不强行指派。
- 未启用说话人模块、执行失败或检测结果待复核时，明确展示任务状态，不能静默宣称已满足说话人要求。
- 分类支持主类目、子类目、标签和待确认状态；支持手动指定类目。
- 输出 JSON 与 Markdown；按类目建立结果目录，以 SQLite 记录任务、版本和索引。
- 更换分类、Prompt、模型或 Skill 版本后，按阶段重跑；仅修改总结模板时复用转写。
- 云端请求失败不自动切换到其他供应商上传数据；切换规则由显式配置决定。

## 候选人视角的面试结果

- 岗位、轮次、面试类型和参与角色（缺失则标记未提及）。
- 面试官问题、追问、候选人实际回答，以及对应原文与时间戳。
- 回答中的亮点、信息缺口和可改进项；将分析建议与实际对话事实分开。
- 技术知识点、待补充案例、建议练习的回答与后续学习行动。
- 候选人反问、对方透露的团队和岗位信息、后续安排。
- 不把面试官观点归为候选人回答，不虚构结论或录用概率。

## 验收重点

1. 一条约 60 分钟的中文多人面试可以完成全流程，时间轴完整、说话人 ID 可追踪。
2. 用人工标注的短样本评估中文识别、说话人归属和候选人问答匹配；重点覆盖交替、打断、长静音和专有名词。
3. 长录音分段不导致说话人 ID 在每段重新编号；对齐和汇总保留全局时间。
4. 更正候选人角色后，仅重跑后续阶段即可更新结果。
5. 模型和运行目录均在工作区内，未修改系统 Python、用户全局包、Shell 配置或全局模型目录。
6. 后续在 Mac 和 Windows 分别执行安装与运行验收；本机验证不能替代 Windows 验证。

当前模型路线与实现边界见架构和状态文档。速度验收目标、人工评估阈值和代码许可证尚待确定；已完成一条真实录音的端到端原型运行，尚未完成系统人工准确率评估。
